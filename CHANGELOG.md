### Added
- `pkg/notifyrender` — **the Repair vertical («Ремонт спецтехники») catalog: 31 `NOTIFICATION_TYPE_REPAIR_*` types, values 134–164.** Each gains a `typeKey` (`repair_<snake>`), a `requiredParams`/`optionalParams` contract, a `BaselineEN` title/body pair and an `ExtractParams` case. **This lands BEFORE either producer**, and that ordering is the point rather than tidiness: `notifyoutbox.PublishDirective` validates the type INSIDE the caller's transaction (`notifyoutbox.go:133`), so order-service emitting a repair directive against an unmapped catalog would not lose a push — it would roll back the customer's own cancel, confirm or offer. 23 of the types are order-service's deal family (§3.3 rows 0–22) and 8 are sale-service's bank/posting family (rows 23–30); all are tenant-addressed with `recipient_role_filter = [ADMIN, MANAGER]` and `channels = [IN_APP, PUSH]`. **Every name a repair template carries is a TENANT DISPLAY NAME** — `customer_name` / `provider_name` / `actor_name` / `seller_name` are the counterpart tenant's public name as frozen on the deal at create time, or on the response (master §3.3, sub-plan 03d), never a contact person's name and never a phone; nothing is resolved inside the emitting transaction, which is what freezing them is for. No template reads an id (the responder deep links carry `seller_tenant_id` and `response_id` as link params, which inbox-service persists separately). **Four branch discriminators, and they are OPTIONAL by mechanism**: `had_offer` (Р47's two customer editions), `deal_completed` (the vault's two repairer-side review rows), `cancelled_by` (the two cancel texts, which differ only in the subject) and `supersedes_previous` (D62, on both the pre-confirm offer and the mid-job price). Master §3.3 assigns them the optional tier and the code requires it: a required param must appear as a literal `{{.name}}` (`validate.go:74-78`, `baseline_test.go:64-70`) and none of them is ever printed — they pick between editions of a sentence. All four are strings on the wire carrying `true`/`false` (and `customer`/`provider`), passed through verbatim; only the tier is weaker, and `TestRepairBranchFlagsNeverAssertTheWrongEdition` pins the consequence: **both arms are tested explicitly**, so an absent or unrecognised value lights NEITHER — a customer whose request nobody answered is never told that «the offer is no longer valid», and a cancel with no recorded side never names one. That is `flagWhen`'s «USE IT IN PAIRS» rule (its doc comment in `extract.go`) in its string form; parts reaches the same place with `""`/`"1"` pairs. `distance_km` is the family's only numeric optional and goes through `countOrEmpty` — «~0 km» would otherwise print for every seller standing on the posting's own point. **Nine of the 31 sections have no vault row** — 18 of the 62 English strings — and are composed here from the rule rather than from the owner's Russian (D62, D4 ×3, D63 ×2, D17, D6, and D32's rewrite of «Продлить на 7 дней?» to 14 days); they are vault-patch targets, listed in `docs/superpowers/plans/2026-09-13-repair-02-go-common-i18n.md`. `repair_auto_confirmed` carries NO review call to action: it is one type addressed to BOTH tenants, and repair reviews are one-directional (заказчик → ремонтник, D24), so a second-person «you can leave a review» would tell the provider tenant it may do something it cannot — the customer's invitation is `repair_review_invite`'s own text, and inviting an auto-confirmed customer is the producer's to emit. `repair_request_completed` trims «Оставлен отзыв ★[N]» off the vault's «Работы подтверждены» because the rating is a separate later directive and cannot render at confirm time. `repair_liveproof_test.go` carries the family's four censuses and three locks: the censuses are the proto walk (31 declared, 31 mapped), the two hand-written producer lists, the wire-fixture round trip per type in both locales, and the set equality tying every declared type to exactly one fixture and one `ExtractParams` arm; the locks are the zero distance, the branch editions (both arms of all four discriminators, plus an absent and an unrecognised value), and the degradation sweep with every optional absent. The `gen-go-lib` pin moves to the regeneration that carries the 31 enum values, the 31 `SendRepair*` messages and the 31 oneof arms — `ExtractParams` is a hand-written dispatch over getters, so the older pin does not compile against it.

The gauge sampler is a third goroutine under `Start`, stopped by the same `stop()`. Both backlog gauges publish from process start, including on an empty table; `outbox_last_success_timestamp_seconds` is set at relay start and on every error-free poll including zero-row cycles.
  - `PublishProto` injects `traceparent` from the **producing request's** context, so one trace spans request → outbox → relay → consumer. Captured at insert, never at relay.

### Changed
- `pkg/notifyrender` / `go.mod` — the `gen-go-lib` pin moves `v0.0.0-20260821100229-a79231a125a5` → `v0.0.0-20260907041205-d941c0186280`. Required, not housekeeping: `SendPartsOrderContactHandover` gained `order_no = 4` and `request_count = 5` in that regeneration, and `ExtractParams` is a hand-written dispatch over the payload's getters — `GetOrderNo()` and `GetRequestCount()` do not exist at the older pin.
- **(observability, fleet-wide)** `response.JSONError` now writes its diagnostic log line through the **request-scoped logger** (`logger.FromContext(c.Request().Context())`) instead of Echo's `c.Logger().Error(err)`, and derives the level from the HTTP **status class** (5xx→`Error`, 4xx→`Warn`, other→not logged). The line was previously an Echo-gommon `ERROR` carrying `prefix:"echo"` and none of `service`/`request_id`/`trace_id` — unfindable by request id, un-joinable to its trace, and it logged every routine 401/404/422 at `ERROR`, inflating the `{level="error"}` error-rate sparkline (§5.4). It now carries the correlation fields, plus `status`, the free-text `error`, and the typed AppError `reason`. Response body and status are unchanged. Every service calling `response.JSONError` gets this on the next go-common bump (go-common#97).
- **BREAKING** (observability Wave 0) `logger.New(level string)` → `logger.New(level, service string)`. Every repo passes a literal equal to its scrape identity in Wave 1; the returned logger carries `zap.String("service", …)` on every line.
- **BREAKING** (observability Wave 0) the logger's **JSON encoder is now unconditional**. The old `APP_ENV == "production"` gate never selected JSON anywhere — compose and both k8s overlays set `local`/`prod` — so every Go service logged the console encoder in every environment, which Loki's `| json` cannot parse. zap's production sampling is disabled so access lines are never silently dropped.
- `middleware.Logger` is **deprecated** in favour of `middleware.RequestLogger`: it carries no `request_id`, so its lines cannot be correlated across the gateway hop, and it is the `echo.WrapMiddleware` shape whose `responseWriter` has to hand-implement `Flush`/`Unwrap` to keep SSE alive. It stays exported until every service has migrated.
- `outbox.Outbox.Start` now runs **three** goroutines (relay, reaper, metrics sampler) under one `stop()`.
- New dependencies: `go.opentelemetry.io/otel`, `/trace`, `/sdk`, `/exporters/otlp/otlptrace/otlptracegrpc` (v1.43.0).
- **BREAKING** (tenant-unification) `pkg/events` topic registry re-family: the enum value formerly wired to `team.events` now resolves to `tenant.events` (the actor) and the value formerly wired to `tenant.events` resolves to `organisation.events` (the profile). Wire names come from the proto `wire_name` option; the helpers (`TopicName`/`DLQName`/`RetryName`) are unchanged.
- **BREAKING** (tenant-unification) `notifyoutbox.validate()` recipient rule is now exactly-one-of `recipient_user_id` / `recipient_tenant_id` where a recipient is required (IN_APP/PUSH); setting BOTH is always rejected with the new Reason `NOTIFYOUTBOX_AMBIGUOUS_RECIPIENT`. Tenant-addressed envelopes (`recipient_tenant_id` + optional `recipient_role_filter`) are resolved to the live member set at delivery time by each channel-owning consumer. `metadata.locale` is now OPTIONAL on every envelope (consumers resolve per-recipient: envelope hint → user preference → platform default); `NOTIFYOUTBOX_EMPTY_LOCALE` is removed.
- **BREAKING** (tenant-unification) `pkg/notifyrender` baseline/catalog keys re-familied: profile family `tenant_*`→`organisation_*` and `admin_transfer*`→`org_admin_transfer*`; actor family invite keys use the kind taxonomy (`tenant_invite_organisation_*` / `tenant_invite_personal_*`, formerly `team_invite_tenant_*` / `team_invite_user_*`); `team_member_*`→`tenant_member_*`; the `team_name` template param is now `tenant_name`. Earlier entries below that mention `TENANT_REJECTED`/`TEAM_MEMBER_REMOVED_ADMIN`/`team_name` describe the pre-pivot vocabulary superseded by this change.
- `notifyoutbox.validate()` relaxed the recipient_user_id rule from "required unless channels is exactly `[SMS]`" to "required when channels contains IN_APP or PUSH". This unblocks anonymous flows (auth-service login OTPs by SMS or email, team-service phone-keyed invites) without changing the safety contract for in-app/push.
- `notifyrender.ExtractParams` gained cases for the three new auth-service payloads (`SendLoginOtpSms`, `SendLoginOtpEmail`, `SendNewDeviceLogin`). They are NOT in the in-app catalog — they go through notification-service's legacy email/SMS template path.
- `notifyrender.ExtractParams` `SendAdminTransferredOld`/`SendAdminTransferredNew` cases now pull the new `team_name` field (was an empty map) so the in-app body names the team instead of rendering static text. Slice 4 adds the four member-lifecycle payload cases plus the slice-5 `SendPlatformMessage` verbatim case.
- `notifyoutbox.validateParams` gained a verbatim escape hatch: `PLATFORM_MESSAGE` skips the catalog/required-param contract and is validated only for non-empty title-or-body (`NOTIFYOUTBOX_EMPTY_VERBATIM`).
- **BREAKING** (tenant-unification) JWT membership claim reshaped: `auth.TeamClaim{T,O,R json:"t,o,r"}` → `auth.TenantClaim{ID string json:"id"; R string json:"r"; Kind string json:"kind,omitempty"}`; the owner-type axis is gone (ownership keys on the bare tenant id) and `Kind` is client-display-only (server consumers never branch on it). The `Claims` slice field `Teams []TeamClaim json:"tms,omitempty"` → `Tenants []TenantClaim json:"tns,omitempty"`. `auth.ContextKeyTeamMemberships` (`"team_memberships"`) → `auth.ContextKeyTenantMemberships` (`"tenant_memberships"`).
