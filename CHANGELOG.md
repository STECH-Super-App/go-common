# Changelog

## [Unreleased]

### Added
- `pkg/authz` — `X-Tenant-Memberships` header codec (tenant-unification, spec §4/§12.1). `TenantMembership{TenantID, Role string}`, `ParseTenantMemberships(header) []TenantMembership`, `FormatTenantMemberships(ms) string`, `const HeaderTenantMemberships = "X-Tenant-Memberships"`, and context reader `TenantMembershipsFromContext(c)`. This is the fleet-wide single parser/formatter of the membership header. New wire form is `<tenant_id>=ROLE,...` (e.g. `11111111-...=ADMIN,22222222-...=MANAGER`) — replaces the owner-pair form `TENANT:<uuid>=MANAGER,USER:<uuid>=ADMIN`. `AuthMiddleware` now parses it into `auth.ContextKeyTenantMemberships`.
- `pkg/notifyrender` — typed template rendering for NotificationEnvelope payloads. Templates (TOML, en/ru/kk) embedded; `Render(type, params, locale)` + `ExtractParams(env)` + `RequiredParams(t)` public API. Both notification-service and inbox-service depend on it.
- `pkg/notifyoutbox` — typed producer wrapper for `TOPIC_NOTIFICATION_EVENTS`. `PublishDirective(ctx, pub, tx, env)` validates 10 rules before writing the outbox row. After Phase 4, direct `outbox.Publisher.PublishProto` for that topic is forbidden.
- Tolgee CI workflows (`.tolgeerc.json`, `i18n-{push,pull,consistency}.yml`, `scripts/check-i18n-consistency.sh`) — moves the in-flight Tolgee setup from notification-service to go-common, since templates now live here. Project ID placeholder; inert until ops provisions the Tolgee project.
- Inbox-notif slices 2 & 4 — nine new in-app `NotificationType` catalog entries with TOML (en/ru/kk): `TENANT_REJECTED`, `INVITE_ACCEPTED`, `INVITE_DECLINED`, `ADMIN_TRANSFERRED_NEW`, `ADMIN_TRANSFERRED_OLD` (slice 2 — EMAIL flows now also render IN_APP), and `MEMBER_BLOCKED`, `MEMBER_UNBLOCKED`, `MEMBER_REMOVED`, `TEAM_MEMBER_REMOVED_ADMIN` (slice 4 — team membership lifecycle). EN is real source-of-truth prose; ru/kk seeded with the `TODO_*` placeholder convention pending Tolgee.
- Inbox-notif slice 5 (verbatim free-text) — `notifyrender.IsVerbatim(t)` + `notifyrender.RenderVerbatim(params)` + `ReasonEmptyVerbatim`/`ErrEmptyVerbatimText`. `NOTIFICATION_TYPE_PLATFORM_MESSAGE` carries admin-authored literal title/body and is deliberately NOT in the catalog; consumers branch on `IsVerbatim` before `Render` and copy the text straight into the inbox row.

### Changed
- **BREAKING** (tenant-unification) `pkg/events` topic registry re-family: the enum value formerly wired to `team.events` now resolves to `tenant.events` (the actor) and the value formerly wired to `tenant.events` resolves to `organisation.events` (the profile). Wire names come from the proto `wire_name` option; the helpers (`TopicName`/`DLQName`/`RetryName`) are unchanged.
- **BREAKING** (tenant-unification) `notifyoutbox.validate()` recipient rule is now exactly-one-of `recipient_user_id` / `recipient_tenant_id` where a recipient is required (IN_APP/PUSH); setting BOTH is always rejected with the new Reason `NOTIFYOUTBOX_AMBIGUOUS_RECIPIENT`. Tenant-addressed envelopes (`recipient_tenant_id` + optional `recipient_role_filter`) are resolved to the live member set at delivery time by each channel-owning consumer. `metadata.locale` is now OPTIONAL on every envelope (consumers resolve per-recipient: envelope hint → user preference → platform default); `NOTIFYOUTBOX_EMPTY_LOCALE` is removed.
- **BREAKING** (tenant-unification) `pkg/notifyrender` baseline/catalog keys re-familied: profile family `tenant_*`→`organisation_*` and `admin_transfer*`→`org_admin_transfer*`; actor family invite keys use the kind taxonomy (`tenant_invite_organisation_*` / `tenant_invite_personal_*`, formerly `team_invite_tenant_*` / `team_invite_user_*`); `team_member_*`→`tenant_member_*`; the `team_name` template param is now `tenant_name`. Earlier entries below that mention `TENANT_REJECTED`/`TEAM_MEMBER_REMOVED_ADMIN`/`team_name` describe the pre-pivot vocabulary superseded by this change.
- `notifyoutbox.validate()` relaxed the recipient_user_id rule from "required unless channels is exactly `[SMS]`" to "required when channels contains IN_APP or PUSH". This unblocks anonymous flows (auth-service login OTPs by SMS or email, team-service phone-keyed invites) without changing the safety contract for in-app/push.
- `notifyrender.ExtractParams` gained cases for the three new auth-service payloads (`SendLoginOtpSms`, `SendLoginOtpEmail`, `SendNewDeviceLogin`). They are NOT in the in-app catalog — they go through notification-service's legacy email/SMS template path.
- `notifyrender.ExtractParams` `SendAdminTransferredOld`/`SendAdminTransferredNew` cases now pull the new `team_name` field (was an empty map) so the in-app body names the team instead of rendering static text. Slice 4 adds the four member-lifecycle payload cases plus the slice-5 `SendPlatformMessage` verbatim case.
- `notifyoutbox.validateParams` gained a verbatim escape hatch: `PLATFORM_MESSAGE` skips the catalog/required-param contract and is validated only for non-empty title-or-body (`NOTIFYOUTBOX_EMPTY_VERBATIM`).
- **BREAKING** (tenant-unification) JWT membership claim reshaped: `auth.TeamClaim{T,O,R json:"t,o,r"}` → `auth.TenantClaim{ID string json:"id"; R string json:"r"; Kind string json:"kind,omitempty"}`; the owner-type axis is gone (ownership keys on the bare tenant id) and `Kind` is client-display-only (server consumers never branch on it). The `Claims` slice field `Teams []TeamClaim json:"tms,omitempty"` → `Tenants []TenantClaim json:"tns,omitempty"`. `auth.ContextKeyTeamMemberships` (`"team_memberships"`) → `auth.ContextKeyTenantMemberships` (`"tenant_memberships"`).

### Removed
- **BREAKING** (tenant-unification) `pkg/authz` owner-pair apparatus deleted: `OwnerType`/`OwnerUser`/`OwnerTenant`, `Role`/`RoleAdmin`/`RoleManager`/`RoleOperator`, `Membership`/`Memberships`, `Parse`, `CanAccess`, `MembershipsFromContext`, `OwnerTypeFromBool`, and `auth.HeaderTeamMemberships` (`"X-Team-Memberships"`). Per-tenant access decisions now live in each service (against `ParseTenantMemberships` output or via tenant-service); go-common keeps only the header codec and the global-role predicate (`HasMinGlobalRole`).
